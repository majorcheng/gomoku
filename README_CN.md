# Gomoku · 五子棋（自研引擎）

纯前端 Web 五子棋对弈应用：**完全自研的迭代加深 α-β + VCF 算杀引擎**跑在
Web Worker 里，零第三方依赖、零构建、零下载，可直接托管在 GitHub Pages。

> English readme: [README.md](README.md)。
> **在线试玩：<https://justa-cai.github.io/gomoku/>** · 源码：<https://github.com/justa-cai/gomoku>

## 核心特性

- **自研引擎**：迭代加深 Negamax α-β + Zobrist 置换表 + 杀手/历史启发 +
  **VCF 连续冲四算杀**。没有 Stockfish、没有第三方库、没有 WASM 产物。
- **零依赖**：无构建步骤、无 CDN、无图片字体资源（棋子是 Canvas 径向渐变
  程序画的），整个应用直接加载仓库中的源码。
- **数据诚实**：侧栏如实展示每一手真实的搜索深度/节点/NPS/耗时/分数；
  低难度走了非首选落子会明确标注「次优」，算杀标注「VCF」。
- **三种模式**：人机（六档难度、可执黑执白）、本机双人、机机对战
  （难度校准与观赏用）。
- **规则**：15×15 棋盘沿用连珠禁手规则，黑方禁长连、双三、双四；黑方恰好五连或白方五连（含长连）者胜，落满 225 点和棋。坐标为 A–O / 1–15；默认开局取中心 H8。

## 难度设计

| 档 | 名称 | 深度 | 时限 | VCF | 采样 |
|:--:|:--:|:--:|:--:|:--:|:--|
| 1 | 入门 | 1 | 200 ms | 关 | 温度 25000，失误率 30% |
| 2 | 初级 | 2 | 500 ms | 关 | 温度 10000，失误率 12% |
| 3 | 中级 | 4 | 1 s | 关 | 温度 3000 |
| 4 | 高级 | 6 | 1.5 s | 开 | — |
| 5 | 大师 | 8 | 2.5 s | 开 | — |
| 6 | 宗师 | 12 | 5 s | 开 | — |

所有档位保留两条不可弱化的硬底线：己方能一步成五必走、对方一步成五必挡。
采样带损失上限，低档位"走得弱"但不会"走得像坏了"。

档位参数的单一事实来源是 `js/difficulty.js`（主线程与引擎 Worker 读同一份）。

## 架构

```text
视图层（Canvas 棋盘 / 侧栏 / 菜单，ES 模块）
        │
裁判层 rules.js（落子合法性、禁手/五连判定、满盘和棋、悔棋）
难度层 difficulty.js（六档参数 + 采样的唯一出处）
        │
引擎门面 bridge.js（seq 配对的异步门面，过期应答静默丢弃）
        │
engine.worker.js（Web Worker：迭代加深 α-β + 置换表 + 杀手启发 + VCF）
```

评估用棋型表（五连 10M / 活四 1M / 冲四 100k / 活三 90k / …），以 5 格滑动
窗口统计——天然覆盖跳棋型（X_XXX），并用"成五完成点是否互不相同"区分活四与
冲四。静态评估 O(1)：每落/撤一子只重算经过该点的 4 条线，旧线分缓存，全局黑白分增量维护。
对手棋子隔开的片段独立计分，避免把两个不相连的眠三合算成活三。

## 30×30 搜索加速与算法参考

本轮阅读了同级 `gomoku-engine/gomoku_all_ai.py` 的具体实现：

| 参考算法 | 实际实现与本项目取舍 |
|---|---|
| 随机、贪心、加权特征 | 随机可作弱对手；贪心/加权特征仅看当前棋型，本项目已有进攻 + 防守评分和一步档位。加权特征是手工权重，不是训练出的神经网络。 |
| Minimax / 迭代加深 | α-β 剪枝与逐层加深适合当前引擎；已有置换表、走子排序与 Worker，沿用并优化。 |
| TSS | 参考实现只检查一步成五、挡五，再回退贪心；本项目已有硬应手与递归 VCF 连续冲四。 |
| MCTS | 参考实现每轮复制棋盘并做最多 50 步随机模拟；30×30 下这些操作会增加成本，未将其作为加速替代。 |
| Hybrid | 参考实现串行调用多个算法再投票，耗时会累加；本轮未新增多引擎投票。 |

点评分按黑/白缓存，落子和撤子只令四个方向各四格内的缓存失效；普通候选仅保留前 K 项。
合法的一步赢、必挡优先处理；高级及以上保留全部真实冲四，普通候选宽度不裁掉强制变化。

以下是规则与战术修复前的纯计算优化历史基准，不代表当前棋力或当前耗时：
2026-09-15，本机 Node v26.8.2，深度 4、候选宽度 20、VCF 关闭，两个局面各预热 2 次、
测量 5 次取中位数；两边都使用 30×30，基线是 `e1004af` 的引擎仅调整 SIZE/CENTER：

| 局面 | 根候选数 | 基线 | 优化后 | 加速比 |
|---|---:|---:|---:|---:|
| 集中落子（14 手） | 72 | 20.4 ms | 15.1 ms | 1.35× |
| 分散落子（14 手） | 194 | 44.9 ms | 19.4 ms | 2.32× |

当时的对照确认完整候选、分数与节点数一致；当前版本修正了规则、评分与战术搜索，
应按合法性、战术预期与同预算对弈验收，历史等价结果不能证明当前棋力。

## 宗师规则与战术修复

`engine.worker.js` 使用原生 module Worker，直接导入 `rules.js`。根候选、内部搜索、
VCF 攻防和主线程落子共用裁判，禁手不占合法候选名额。主线程发现非法结果会报告引擎错误，
不再自动改下第一个空点。规则按 [RIF 第 3、9 节](https://www.renju.net/rifrules/) 校正：
跳活三只需一个合法活四延伸点，形成长连、双四或递归禁手的延伸不算真活三；黑方同时形成
恰五时获胜优先，白方五连及以上获胜。15×15 棋盘仍采用本项目的自由开局。

宗师为普通深度上限 12、总预算 5 秒、普通候选 32/16、零随机失误。
先完成基础搜索，再运行 VCF，子预算为 `min(400 ms, 剩余时间 × 20%)`；子预算耗尽后
继续普通搜索。下一层是否继续参考上一层实际耗时，总 deadline 兜底，超时保留完整层结果。

高级及以上在基础两层之后启用最多额外 4 手的强制变化搜索；叶子的一步赢、无法同时防住
的两个成五点、合法必挡均先识别。延伸仅检查必要应手和能产生实际合法成五点的冲四，
仍计入同一时间预算。普通搜索深度不等于所有分支都额外搜索了 4 手。

消息统计包含 `nodes`、`tacticalNodes`、`vcfNodes`、`stopReason`、`vcfStopReason`。
静态分限制在胜负阈值内，只有合法成五或已证实的强制变化会得到必胜/必败分。

```bash
node scripts/check.mjs
# 本机真实宗师预算检查
node scripts/check.mjs --bench
# 同规则、同预算的 12 开局换先对照；时间较长
node scripts/match.mjs /path/to/baseline.worker.js /path/to/results.json
```

回归同时覆盖规则、搜索逐手合法性、缓存与全盘重算、两种超时、真实模块在线程中的消息协议。
Bridge 的取消/过期应答使用测试替身验证；这些检查不代表浏览器视觉验收。

以下为 30×30、每手 4 秒时的历史对照，不代表当前 15×15、每手 5 秒的棋力。
2026-09-15，本机 Node v26.8.2，12 个固定开局换先共 24 局，双方每手 4 秒，普通宽度
32/16。对照方是已完成规则与时间预算修复、尚未加入本轮战术延伸及分段评分的版本。
当前版 **19 胜、4 负，1 局追加 80 手后仍未结束**；未结束局不记为和棋。
双方合计 827 次搜索均返回合法落子，最大耗时约 4005.34 ms。
原始棋谱、每手统计、版本 SHA-256 和运行条件见 `tasks/strength-matches.json`。
这些固定开局中部分来自同一序列的不同阶段，结果用于筛选，不能推断通用胜率或 Elo。

## 调研记录（为什么这样做）

立项前做过一轮技术调研，结论浓缩如下：

1. **五子棋没有官方强引擎的 WASM 构建**（不像国际象棋有 Stockfish.js），
   Gomocup 级 C++ 引擎要自己用 Emscripten 交叉编译，维护成本高于自研；
2. **Alpha-Beta + 启发式 + VCF 的组合棋力足够**——研究与实践（如
   lihongxun945/gobang ~1.8k star 的纯 JS 实现）表明 6-8 层有效深度已远超
   休闲玩家；本引擎实测 L4（6 层 + VCF）对 L1 双色全胜；
3. **AlphaZero 路线训练成本高**（8×8 棋盘需自对弈 2000-3000 局），
   且与"纯静态、即开即玩"的部署目标冲突，故不采用。

详细调研过程（算法对比、开源项目星数核实）见 `specs/prd.md` 的引用文献。
